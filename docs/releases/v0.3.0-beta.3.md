# Hi10 Download Manager v0.3.0-beta.3

**Testing prerelease — not a stable/production release.** Linux/amd64.

## Changes

- Opt-in project monitoring automatically checks for existing missing files and
  future additions, using current quality and section selections. Includes per-row
  and bulk Monitor/Unmonitor controls, a Monitored filter, configurable intervals,
  pause/resume, and Check now. Monitoring continues with the browser closed.
- Automatic batches preserve manual queue entries, respect exclusions and saved
  schedules, and remember handled files across restarts and queue clearing.
  Failed/interrupted attempts require manual Retry. Stop batch on an automatic
  batch pauses monitoring until resumed. No projects are monitored by default.
- Recognize explicit MKV destinations wrapped by fc.lc and Spaste alongside ouo.
  Duplicate wrappers resolve to one file; ZIP patches are ignored and distinct
  destination hosts remain available as same-quality mirrors.
- Scan explicit download tables outside the first WordPress content block. This
  fixes the zero-file result for Accelerator archives/85321, confirmed by the
  owner on unRAID. Highest-quality selection still chooses one file per identity.

## Install or upgrade on unRAID

Image: `ghcr.io/chard1988/hi10anime-downloader:0.3.0-beta.3`.
Use [the installation/upgrade guide](https://github.com/chard1988/hi10anime-downloader/blob/master/docs/UNRAID_INSTALL.md)
or attached INSTALL.md. Stop the old container, back up all appdata and
hi10-manifest.json, then edit Repository while preserving /config, /downloads,
port, password and folder structure. Reinstalling/deleting appdata is unnecessary.
Non-root UID/GID 99:100 must be able to write both mappings. Keep the prior image
and full pre-upgrade backup for rollback; do not downgrade migrated data in place.

Older libraries migrate on first startup. Verify downloaded counts and queue state
before enabling monitoring; existing scheduled starts persist. Rescan previously
zero-file projects after upgrading. The browser-session exporter remains available
for importing your current signed-in Chrome/Edge session.

## Known beta limitations

This version retains the approved testing-beta policy: complete image scan findings
and hardened Chromium sandbox results are disclosed in the attached reports. No
findings are suppressed or waived for stable release. Use session import if the
hardened embedded browser cannot launch; keep non-root/cap-drop/no-new-privileges
settings. Browser login/CAPTCHA success and mirror availability are not guaranteed.
Use a private LAN/Tailnet and authorized content only.

Only amd64 is tested. Multi-day soak, ARM, Tailscale hooks, CA acceptance, signed
attestations and stable readiness remain separate gates. The owner verified the
specific table-scope fix on unRAID; that is not certification of every NAS upgrade.
Interrupted files restart from the beginning. Monitoring supports 200 projects,
100,000 tracked file identities, and a 15-minute minimum check interval.
